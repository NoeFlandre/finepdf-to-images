# ADR-0010: Declare explicit dataset configs in the card front matter

Status: accepted (2026-09-17)

## Context

The Hugging Face Dataset Viewer and the Parquet converter failed with `CastError` on the published dataset (`NoeFlandre/finepdf-to-images-poc`).

The dataset card (`README.md`) declared no `configs:` block in its YAML front matter. Thus `datasets-server` of the Hub detected all files in `data/` automatically as one `default` split. Then it tried to concatenate `data/documents.jsonl` and `data/images.jsonl`. These files have different schemas on purpose. The cast failed (`"viewer": false`). The Parquet generation failed. The image index was not reachable in the Hub UI.

The publication tests asserted that the bytes of the uploaded files matched the locally generated bytes. No test asserted that the dataset server of the Hub could parse them as different datasets.

## Decision

Declare explicit `configs:` in the YAML front matter that `render_card` emits:

- `documents` points to `data/documents.jsonl`.
- `images` points to `data/images.jsonl`.

Add a domain unit test. The test parses the generated card front matter with a real YAML parser. It asserts that both configs and their target data files are present.

## Consequences

- `datasets-server` of Hugging Face recognizes two separate configs (`documents` and `images`). It does not fall back to the automatic detection with colliding schemas.
- The Parquet conversion succeeds for both tables. The Dataset Viewer works again.
- The project treats the card front matter as a machine-read contract. It does not treat it as unparsed prose or arbitrary text.
