# ADR-0010 — Declare explicit dataset configs in the card front matter

Status: accepted (2026-09-17)

## Context

The Hugging Face Dataset Viewer and parquet converter failed with `CastError` on the published dataset
(`NoeFlandre/finepdf-to-images-poc`).

Because the dataset card (`README.md`) declared no `configs:` block in its YAML front matter, the Hub's
`datasets-server` auto-detected all files under `data/` as a single `default` split. It then attempted
to concatenate `data/documents.jsonl` and `data/images.jsonl` together. These files have deliberately
distinct schemas, so casting failed (`"viewer": false`, parquet generation failed, and the image index
was completely unreachable in the Hub UI).

Publication tests had asserted that uploaded file bytes matched locally generated bytes, but nothing
asserted that the Hub's dataset server could parse them as distinct datasets.

## Decision

Declare explicit `configs:` in the YAML front matter emitted by `render_card`:
- `documents` pointing to `data/documents.jsonl`
- `images` pointing to `data/images.jsonl`

Add a domain unit test that parses the generated card front matter with a real YAML parser and asserts
that both configurations and their target data files are present.

## Consequences

- The Hugging Face `datasets-server` recognizes two separate configurations (`documents` and `images`)
  rather than falling back to schema-colliding auto-detection.
- Parquet conversion succeeds for both tables and the Dataset Viewer is restored.
- The card front matter is treated as a machine-read contract rather than unparsed prose or arbitrary text.
